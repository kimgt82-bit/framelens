# 프레임 렌즈 (Frame Lens) - 같은 뉴스, 다른 시선

키워드 하나로 최근 7일 뉴스 헤드라인의 핵심 쟁점과 보도 프레임을 한눈에 보여 주는 헤드라인 분석 웹앱입니다.

대학원 과제용으로 개발하며, **기사 본문은 분석하지 않습니다.** 분석 결과는 학습과 비교를 위한 참고 자료입니다.

## 주요 기능

- 최근 7일 Google 뉴스 헤드라인 최신순 최대 30건 수집·중복 정리.
- 5대 뉴스 프레임과 판단 보류, 제목의 감성·확신도·짧은 근거 분석.
- 프레임·감성 분포, 언론사별 비교, 대표 헤드라인과 기사 링크.
- 해외 이슈 제외와 제외 목록·판단 불가·서버 보정 정보 공개.
- 종합 해설 3문장과 추가로 살펴볼 관점 제안.
- 블라인드 제목 수집, 같은 목록 분석, 수동·AI 분류 결과 TSV 복사.
- 최근 성공 검색어 5개, 오류 안내, 연속 요청 방지와 IP당 1분 5회 분석 제한.

현재 핵심 브리핑·원클릭 분석·하단 연구자 도구·결과 공유·메일 작성이 구현되어 있습니다. 실제 브라우저별 표시·외부 API 성능은 별도 확인이 필요합니다.

## 화면 구성

현재 화면은 중앙 검색 첫 화면과 다섯 결과 섹션으로 구성합니다. 흰색·옅은 회색과 검정 계열 글자, 파란 포인트(#315bda), Pretendard 산세리프를 사용합니다.

- **첫 화면:** 가운데 로고·짧은 부제·큰 둥근 입력창·분석하기 버튼, 예시·최근 검색 칩. 칩은 입력만 채웁니다.
- **로딩:** 전체 화면에서 회색 자리표시가 먼저 흐르고, 수집 후 실제 제목들이 흐릅니다. 수집 → 프레임 분석 → 결과 정리의 3단계와 ‘보통 15~30초’ 안내를 표시합니다. 이는 예상 시간이며 보장은 아닙니다.
- **01 핵심 브리핑:** 키워드·분석 일시, 한 줄 프레임 분포 막대와 비율, 핵심 쟁점·근거 번호, 공유·메일, 해외 제외 안내·요약 숫자.
- **02 보도의 분포:** 프레임·감성 가로 막대 차트.
- **03 관점 나란히 보기:** 프레임별 대표 헤드라인과 언론사·기사 링크를 PC 3열로 비교합니다.
- **04 비교와 해석:** 언론사별 비교표·종합 해설·추가 관점 제안.
- **05 근거와 방법:** 전체 기사·제외 목록·방법론·한계와 기본 닫힌 연구자 도구.

각 섹션은 실제 집계값을 반영한 큰 헤드카피가 먼저 등장하고 세부 데이터가 이어집니다. 결과에서는 입력창이 상단 고정바로 줄어듭니다. PC는 섹션 스냅·오른쪽 점·이전/다음 버튼과 섹션 내부 스크롤을 사용하고, 폭 768px 이하는 스냅 없이 세로로 읽습니다. 표는 가로 스크롤합니다. 동작 줄이기 설정에서는 제목 흐름·등장 애니메이션·강제 스냅을 생략합니다.

일반 분석은 GET /api/news로 받은 목록을 그대로 POST /api/analyze에 전달하며 AI 호출은 1회입니다. 연구자는 마지막 섹션에서 별도로 블라인드 수집·수동 복사·같은 목록 분석·AI TSV 복사를 진행합니다. 자세한 색상·크기·동작은 [PLAN.md](PLAN.md)의 7절 화면 설계를 참고하세요.

## 사용 방법

### 일반 사용자

1. 키워드를 입력합니다. 예시·최근 검색 버튼은 입력창만 채우며 요청을 보내지 않습니다.
2. **분석하기** 한 번으로 수집과 AI 분석을 수행합니다.
3. 브리핑의 근거 번호와 프레임 분포를 함께 보고 대표 제목의 기사 링크를 확인합니다.
4. 필요하면 결과 공유 또는 메일로 보내기를 선택합니다.

브리핑의 근거 번호를 누르면 전체 기사 목록의 해당 번호로 이동합니다. 공유 미지원 시 클립보드 복사, 복사 실패 시 선택 가능한 텍스트 상자를 제공합니다. 메일은 작성 창만 열며 자동 발송하지 않습니다.

### 연구자 도구: 블라인드 검증

05 / 근거와 방법의 **연구자 도구 (분류 검증용)**를 펼쳐 진행합니다. 첫 화면 아래에서도 도구에 접근할 수 있습니다.

1. 일반 화면의 AI 결과를 보지 않은 새 표본을 수집합니다.
2. 번호·제목만 읽습니다. 블라인드 분류 중에는 언론사 보기 토글을 열지 않습니다.
3. **수동 분류용 목록 복사**를 눌러 엑셀·구글 스프레드시트에 붙여 넣습니다. 열은 번호·제목·내 분류 빈칸입니다.
4. 최신순 앞 20건을 공통 기준으로 직접 분류하고 저장합니다.
5. **이 목록으로 AI 분석**을 누릅니다. 수집한 목록을 그대로 보내며 재수집하지 않습니다.
6. **AI 결과 복사**로 번호·제목·언론사·AI 프레임·감성·확신도·근거를 가져옵니다.
7. 해외 제외 후에도 번호는 그대로입니다. 같은 번호끼리 비교하고 제외 건수와 실제 비교 분모를 기록합니다.

키워드를 바꾸면 다시 수집해야 합니다. 복사 실패 시 나타나는 텍스트 상자에서 Ctrl+C로 복사할 수 있습니다. 최근 검색은 분석 대상이 1건 이상인 성공 키워드만 해당 브라우저에 저장하며 기록 지우기로 삭제합니다.

## 분석 방법 요약

Semetko & Valkenburg(2000)의 5대 프레임을 참고한 **헤드라인 기반 AI 분류**입니다. 원논문의 전체 분석 절차를 재현한 도구는 아닙니다.

| 범주 | 무엇을 강조하는가 |
|---|---|
| 갈등 | 개인·집단·기관 간 대립 |
| 인간적 흥미 | 개인의 경험과 감정 |
| 경제적 결과 | 비용·소득·고용 등 경제적 영향 |
| 도덕성 | 윤리·공정·존엄 등 가치 판단 |
| 책임 귀인 | 문제 원인이나 해결 책임 |
| 판단 보류 | 대표 프레임을 정할 제목 근거 부족 |

- 감성은 제목 어조의 긍정·중립·부정입니다.
- 확신도는 AI 자체 판단이며 정답 확률이 아닙니다.
- AI에는 키워드와 번호·정리된 제목만 보내고 별도 언론사명은 보내지 않습니다.
- 해외 기사는 집계에서 제외하고 지역 판단 불가는 포함합니다. 외국 단서가 없는 제목은 운영상 국내로 봅니다.
- 서버 보정과 해외 제외 목록을 공개하며 분포·비율은 서버가 계산합니다.
- 브리핑은 포함 제목만 근거로 작성하고 근거 기사 번호를 반드시 붙입니다.
- 판단 보류(프레임)와 판단 불가(지역)는 다른 항목입니다.

검증은 일치율과 코헨 카파로 정리합니다. 이는 1인 수동 분류와 AI 사이의 일치도이며 객관적 정확도는 아닙니다. 자세한 기준·계산식은 [PLAN.md](PLAN.md)에 있습니다.

## 기술 스택

- 화면: HTML·CSS·JavaScript, HTML/CSS 막대 차트.
- 서버: Node.js + Express, server.js 하나.
- 패키지: express, dotenv, rss-parser, openai(공식 JavaScript SDK).
- AI: gpt-6-luna, Responses API, Structured Outputs.
- 현재 설정: 추론 none, AI 90초·RSS 10초 제한, 자동 재시도 없음. 전체 요청은 두 제한의 합보다 짧다고 보장하지 않습니다.
- 배포 목표: GitHub + Vercel.
- React·Next.js·TypeScript·데이터베이스는 사용하지 않습니다.

## 로컬 실행 방법

Node.js와 npm을 먼저 설치합니다. 현재 프로젝트는 Node.js 24 LTS 계열 사용을 권장합니다.

1. 프로젝트 폴더에서 패키지를 설치합니다.

```powershell
cd C:\Mission2\framelens
npm install
```

PowerShell에서 npm.ps1 실행 정책 오류가 나면 정책을 변경하는 대신 `npm.cmd install`을 사용할 수 있습니다. 설치에는 네트워크가 필요합니다.

2. 프로젝트 루트의 `.env` 파일에 `OPENAI_API_KEY` 환경변수를 설정합니다. 이미 설정했다면 그대로 사용합니다. 실제 키는 문서·채팅·프런트엔드·로그에 붙여 넣지 마세요. `.env`와 `node_modules/`는 Git 업로드 대상에서 제외합니다.
3. 직접 서버를 실행합니다.

```powershell
node server.js
```

4. 브라우저에서 http://localhost:3000 을 엽니다.
5. http://localhost:3000/api/health 의 `{"ok":true}`로 서버 상태를 확인할 수 있습니다. 이는 AI 키의 유효성 검사는 아닙니다.
6. 종료는 터미널에서 Ctrl+C입니다. 서버 코드를 변경한 경우 종료 후 다시 실행합니다.

첫 실제 AI 분석에는 OpenAI API 사용 가능량과 비용이 필요합니다. 키 설정 예/아니오만 터미널에 표시하며 키 값은 출력하지 않습니다. 오류가 나면 화면의 한국어 안내를 확인하세요. 시간 초과 테스트의 PowerShell 클라이언트 대기는 120초 정도로 설정합니다.

### API 간단 안내

| 주소 | 용도 |
|---|---|
| GET /api/health | 서버 상태 |
| GET /api/news?q=키워드 | AI 없이 제목·언론사·날짜·링크 수집 |
| POST /api/analyze | keyword로 수집·분석하거나 검증된 articles 목록 그대로 분석 |

기사 목록을 보내지 않는 기존 테스트는 `{"keyword":"최저임금","limit":5}` 형식입니다. 목록을 보내는 경우 형식·개수·번호·제목·링크 등을 서버가 확인합니다. 분석 요청은 실패한 입력을 포함해 IP당 최근 1분 5회로 제한하며, 초과 시 기다릴 시간을 안내합니다.

## 알려진 한계

- 제목만 분석하므로 본문 맥락과 사실의 진위를 확인하지 않습니다. AI 오분류가 가능합니다.
- Google 뉴스 비공식 RSS는 장애·변경·검색 편중 가능성이 있으며 최대 30건이 전체 언론을 대표하지 않습니다.
- 언론사별 적은 기사로 언론사 전체 성향을 단정할 수 없습니다.
- 지역 기본값·문자열 서버 보정은 완벽하지 않습니다. 보정 후 AI 해설은 서버 안내로 대체될 수 있습니다.
- 블라인드는 화면 표시 기준입니다. API 응답에는 언론사명이 포함되고 제목 자체에 단서가 있을 수 있습니다.
- 클라이언트 기사 목록은 형식과 건수를 검증하지만 원본 RSS와 동일함을 인증하지 않습니다.
- 1인·20건 검증은 일반 성능·복수 코더 신뢰도를 입증하지 않습니다. 해외 제외로 실제 비교 건수가 줄 수 있습니다.
- 메모리 요청 제한은 서버 재시작·여러 배포 인스턴스에서 공유되지 않아 완전한 비용 보호가 아닙니다. 같은 IP는 제한을 공유합니다.
- 최근 검색은 브라우저·사이트 주소별로 저장됩니다. 결과의 영구 저장·동일 결과 공유 링크는 없습니다.
- 공유·mailto는 기기 지원·권한·메일 앱·길이 제한에 따라 동작이 다를 수 있으며 메일 자동 발송이 아닙니다.
